# Core2 WiFi/字型修復 Plan

## 目標
1. 先恢復所有 UI 文字可見（避免整機變成無字）。
2. 再修正繁體中文缺字（特別是 WiFi 畫面：掃描 / 名稱 / 密碼）。
3. 保留手機配網流程（QR + Web Portal）可用。

## 目前狀態（已完成）
- 已回退「全域強制套用 lv_font_tw_16」：
  - `components/ui/include/ui_compat.h`：恢復 `UI_FONT_TEXT_DEFAULT` 為原邏輯（優先 SimSun，否則 Montserrat）。
  - `components/ui/ui_manager.c`：移除對所有 screen 根節點的強制 `set_style_text_font`。
- `./flash.sh --build-only` 已編譯成功。

## 待做事項（依序）
1. 重新燒錄並驗證「文字可見性」
- 指令：`./flash.sh --flash-only /dev/ttyACM0`
- 驗收：Dashboard / Settings / WiFi 標題與按鈕文字都可見。

2. 鎖定繁中缺字範圍
- 在 WiFi 頁逐一確認哪些字仍是方塊（例如：掃、稱、碼）。
- 紀錄精確字串與位置（按鈕、placeholder、狀態列）。

3. 僅對中文元件套用繁中字型（不要全域覆蓋）
- 先只在 `screen_wifi.c` 針對中文 label / placeholder 測試 `lv_font_tw_16`。
- 其餘頁面維持目前預設字型，避免全站回歸風險。

4. 若 `lv_font_tw_16` 仍異常，改採穩定替代方案
- 方案 A：改用 SimSun 顯示中文（接受部分繁中字缺字）。
- 方案 B：重產 `lv_font_tw_16`（小字集、禁用高風險參數）後只局部上線。

5. 回歸驗證
- 掃描 AP、手動輸入、手機配網（QR）流程全走一次。
- 重開機後確認無已存 WiFi 時會自動顯示配網提示。

## 重點注意事項
- 禁止再做「全域 hard force 字型」：高風險，容易造成全 UI 無字。
- 每次字型調整都要先 `--build-only`，再 flash 實機看結果。
- 字型問題優先保守策略：先保可見，再補缺字。
- README 需與最終實作一致（配網步驟、限制、已知問題）。

## 快速操作指令
- Build：`./flash.sh --build-only`
- Flash：`./flash.sh --flash-only /dev/ttyACM0`
- Monitor：`./flash.sh --monitor /dev/ttyACM0`
